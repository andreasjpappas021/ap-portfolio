Magic Link Authentication Flow

How Supabase, Customer.io, and the Web App work together

📤 Phase 1: Request Magic Link
1
User submits email on login/register page
User → Web App
2
API calls Supabase Admin to generate magic link
POST /api/auth/send-magic-link → supabase.auth.admin.generateLink()
Web App → Supabase
3
Supabase returns magic link URL with auth tokens
Returns: action_link with embedded access_token & refresh_token
Supabase → Web App
4
API sends magic link to Customer.io for email delivery
sendAuthEmail(email, templateId, { magic_link_url })
Web App → Customer.io
5
Customer.io sends transactional email to user
Template ID 6 (login) or 7 (signup) with magic link button
Customer.io → Email
🔐 Phase 2: Complete Authentication
6
User clicks magic link in email
Link contains tokens in URL hash: #access_token=...&refresh_token=...
User → /auth/callback
7
Callback page extracts tokens and sets session
supabase.auth.setSession({ access_token, refresh_token })
Callback → Supabase Client
8
Callback calls create-profile API for new users
POST /api/auth/create-profile → Creates user record in DB
Callback → API → Supabase DB
9
API identifies user in Customer.io
identifyUser() + trackEvent('user_registered')
API → Customer.io
10
User redirected to dashboard (authenticated)
Web App → User
User Browser / Email
Web App Next.js Frontend + API
Supabase Auth + PostgreSQL
Customer.io Email Delivery + Tracking

🔑 Key Architecture Insight

Supabase handles authentication (generating secure magic links with JWT tokens) and stores user data.
Customer.io handles email delivery using transactional templates (more reliable + trackable than Supabase's built-in emails).
The Web App orchestrates the flow: generates links via Supabase Admin API, sends them via Customer.io, and handles the callback to establish the session.
